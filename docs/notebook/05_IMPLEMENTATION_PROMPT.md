# Your Role

You are simultaneously acting as

• Editorial Designer

• Product Designer

• UX Designer

• Storytelling Editor

• Senior Frontend Engineer

• Accessibility Engineer

• Performance Engineer

Every decision should satisfy all of these roles.

---

# What Notebook Is

Notebook is not a blog.

Notebook is not a feed.

Notebook is not documentation.

Notebook is a living collection of personal thoughts.

Readers should feel like they opened someone's notebook,

not someone's website.

---

# Primary Goal

Design an experience that encourages curiosity.

Readers should naturally think

"I'll read just one."

Then continue reading.

Everything should support this behaviour.

---

# Experience Goals

Notebook should feel

calm

editorial

warm

minimal

personal

timeless

Nothing should feel corporate.

Nothing should feel like SaaS.

Nothing should feel like a dashboard.

---

# Reading First

Reading is the product.

Every design decision should improve reading.

Not interaction.

Not animation.

Not visual effects.

Reading.

---

# Hero

Notebook begins quietly.

Avoid large marketing headlines.

Instead communicate

This is a collection of thoughts.

Not a collection of content.

The hero should invite.

Never sell.

---

# Categories

Implement lightweight category filtering.

Examples

Life

Learning

Travel

Leadership

Work

Questions

Random

Use smooth transitions.

No page reloads.

No complex interactions.

---

# Featured Notes

Display a curated collection.

Do not automatically choose the newest entries.

Featured means

worth discovering first.

---

# Notes

Render markdown beautifully.

Typography should always take priority.

Large margins.

Comfortable spacing.

Excellent readability.

Support

headings

lists

quotes

images

code blocks

links

horizontal rules

callouts

without visual clutter.

---

# Images

Images are optional.

When unavailable,

use elegant editorial placeholders.

Never use stock photography.

Never use decorative filler.

The absence of an image should never reduce the quality of a note.

---

# Cards

Cards should feel like printed paper.

Subtle.

Soft.

Warm.

No heavy borders.

No loud shadows.

Minimal interface.

---

# Motion

Motion exists only to improve orientation.

Use

fade

soft transitions

small elevation

gentle movement

Avoid

parallax

dramatic scaling

rotations

flashy reveals

Motion should disappear into the experience.

---

# Typography

Reading width

Maximum

680px

Line spacing should feel generous.

Paragraph rhythm should match the editorial system.

Never compress text.

---

# Metadata

Support

title

category

date

reading time

location

tags

featured

Display only what improves reading.

Avoid unnecessary metadata.

---

# Related Notes

Every note ends with

"You might also enjoy..."

Recommend notes based on

theme

emotion

category

not chronology.

Readers should naturally continue reading.

---

# Empty States

Every empty state should feel intentional.

Never display

"No data."

Instead use thoughtful editorial language.

Example

Life hasn't given me something worth writing here yet.

---

# Search

Prepare architecture for future search.

Placeholder text

Search thoughts, places or memories...

Avoid technical wording.

---

# Accessibility

Semantic HTML

Keyboard navigation

Reduced motion

Screen reader support

High contrast

Readable typography

Large touch targets

Accessibility is mandatory.

---

# Performance

Notebook should remain lightweight.

Lazy load where appropriate.

Optimize images.

Minimize JavaScript.

Preserve smooth scrolling.

Maintain excellent Lighthouse scores.

---

# Future Growth

Notebook will continue growing for years.

Do not build for

20 notes.

Build for

500+

Notes.

Architecture should remain clean and scalable.

---

# Things To Avoid

Never create

blog cards

marketing banners

social feeds

engagement widgets

like buttons

share counters

comment sections

recommended advertisements

Notebook should remain deeply personal.

# Final Test

Before considering Notebook complete,

close the editor.

Forget the implementation.

Imagine opening the page for the first time.

Ask yourself

Does this feel like reading someone's notebook?

If the answer is

"No"

continue refining.

If the answer is

"Absolutely"

only then consider the work complete.

# The HOME Principle

Notebook should never try to become the most impressive part of HOME.

It should quietly become the part people return to most.
