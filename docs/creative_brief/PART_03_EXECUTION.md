# Before You Build

If you've reached this document, it means you've already read:

README.md

PART_01_FOUNDATION.md

PART_02_DESIGN.md

If you haven't,

stop here.

Those documents explain why HOME exists.

This document explains how to build it.

Without understanding the philosophy,

good implementation is impossible.

---

# Your Responsibility

You are not simply implementing components.

You are protecting an experience.

Every decision you make should answer one question:

"Will this help visitors feel more connected to the story?"

If the answer is no,

don't build it.

---

# Build Like An Editor

Do not think like an engineer.

Think like an editor.

Editors remove.

Editors simplify.

Editors clarify.

Whenever possible,

remove complexity instead of adding it.

---

# HOME Is Story First

The most important element on every page is the story.

Never allow animations,

graphics,

interactions,

or visual effects

to become louder than the words.

Technology supports.

Stories lead.

Always.

---

# Quality Standard

Every page should feel:

Finished.

Intentional.

Calm.

There should never be placeholder text.

There should never be placeholder layouts.

There should never be placeholder interactions.

If content exists,

use the real content.

Only images may temporarily use placeholders.

Everything else should feel production-ready.

---

# Implementation Principles

Prioritize:

Readability

Performance

Accessibility

Consistency

Simplicity

Maintainability

Avoid unnecessary abstraction.

Avoid unnecessary dependencies.

Avoid unnecessary animations.

Avoid unnecessary complexity.

Future contributors should immediately understand the project.

---

# Decision Framework

Whenever you're unsure about a decision,

follow this order.

1

Protect the story.

↓

2

Protect the reading experience.

↓

3

Protect simplicity.

↓

4

Protect performance.

↓

5

Improve visuals.

Visual improvements should never reduce clarity.

---

# Future Contributions

Every future feature should answer:

Does this deepen the visitor's understanding?

Does this create emotional value?

Does this preserve HOME's philosophy?

If not,

it probably belongs somewhere else.

---

# Things Never To Do

Never redesign HOME because of trends.

Never replace stories with marketing.

Never optimize for engagement.

Never create unnecessary interactions.

Never add features simply because they are popular.

Never sacrifice simplicity for innovation.

Never sacrifice honesty for aesthetics.

Never forget why HOME exists.

---

# Long-Term Thinking

HOME should still feel beautiful in ten years.

That means:

Choose timeless typography.

Choose timeless layouts.

Choose timeless writing.

Choose timeless interactions.

Avoid trends that quickly become outdated.

---

# When In Doubt

Read Becoming.

Read Notebook.

Read Project Philosophy.

Read the Creative Brief again.

The answer is almost always already there.

# Final Letter

Dear Builder,

Thank you.

Whether you're human or AI,

you've been trusted with something deeply personal.

HOME isn't trying to become the biggest website.

It isn't trying to become the most impressive.

It's trying to become the most honest.

Every story here represents a real moment.

Every lesson represents lived experience.

Every page exists because someone believed those moments were worth remembering.

Please build with care.

Please simplify whenever possible.

Please protect the quiet moments.

Technology will change.

Frameworks will change.

Design trends will change.

The feeling HOME creates should not.

If someone visits HOME years from now and leaves feeling like they spent an evening talking with a friend...

then you've protected the project exactly as intended.

Welcome to HOME.
